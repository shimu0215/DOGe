# Training-question and own-trajectory coverage pilots

The corrected student OPD pipeline remains unchanged. These changes concern only teacher posttraining from original7B, with offline negative text and teacher-only reference distributions/correctness rewards. No student model or outcome feeds the teacher optimizer. Inference is a plain checkpoint.

The prior64-step recipe has16 warmup steps with zero anti loss. Only48 offline negative questions then receive the anti objective, although290 questions are eligible. At each own-RL group, four teacher answers are generated but only the first receives a full-distribution reference anchor. These are observed code facts, not evidence they cause weak suppression. The larger1000-question evaluation (tail-last2 and tail-anti8 both48.2 versusSFT43.5/clean54.1) motivates testing coverage rather than repeatedly selecting the best400 pilot.

Negative-batch4 averages four per-question losses at each active update, using order[(4*step+j) modulo eligible_count] for j=0..3. With the actual290 eligible questions, steps16..63 cover192 distinct offline questions; heldout64 are excluded. Each question still uses up to8 of32 process positions chosen by the original teacher target. Total anti coefficient is unchanged, gradients accumulate sequentially, and only then does the same optimizer update occur. This changes data coverage and averaging, not just the number of positions within one question (the previous wider-position pilot was weak). Selected question IDs and diagnostics are recorded; no future-student classification claim follows.

Live4 averages the reference-KL anchors across all four already generated teacher answers instead of just the first. It keeps the same total live-anchor coefficient, correctness-RL frequency/weight, static anchors, question order and number of optimizer updates. Each group is generated from the current teacher before its update, so later groups reflect earlier teacher changes. This increases coverage of the existing generation/train/regeneration loop; it does not introduce a new student-based RL objective or guarantee teacher quality. Averaging more trajectories can reduce estimator noise under suitable sampling assumptions, but no variance guarantee is claimed for this small adaptive run.

Three last-two-layer pilots separately change negativebatch4, live4, or both, relative to the main40044/expanded100048.2 last2/anti4/anchor24/RL2/answer1 recipe. A fourth last-layer pilot changes only negativebatch4 relative to anti8/anchor24/main44.5/expanded48.2. All retain64 steps, warm16/ramp48, LR5e-6. Three pipelines use original-smoke/freshformal/teacherquality/conditionalfixedstudentOPD with unchanged120seed10 budget; the fourth does too. Real two-step smoke and plain-export checks precede formal training. Expanded teacher noninferiority and reduced student benefit are empirical outcomes still to establish.
