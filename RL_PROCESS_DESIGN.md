# Outcome RL with process-neutralization auxiliary loss

This is a new pilot on allocation **9795227 / gpu008 / A100 80GB**, ending **2026-09-11 02:03 ET**. It does not extend the expired four-allocation experiment. No new reservation is authorized or needed.

## Question

Can an ordinary teacher retain correct final answers while providing less useful OPD supervision on proxy process contexts? A correct final answer and an unhelpful process distribution are separate measured requirements. This pilot does not claim universal protection against unknown students.

## Fixed comparison

Both arms start from original Qwen2.5-7B-Instruct and fit rank16/alpha32 LoRA in the last four transformer layers, then merge into ordinary FP16 weights. No gate, source tag, proxy, adapter, or custom inference architecture is required at deployment.

- **joint**: grouped on-policy outcome RL + 0.02 sampled reference KL + 0.25 process KL.
- **outcome_only**: identical outcome RL and reference KL, without process KL.

The planned budget is128 optimizer updates per arm, group4, learning rate1e-5, norm clip1. Teacher raw sampling: temperature1, top-p1, top-k0, repetition penalty1, up to512 new tokens. One policy update per rollout group uses fixed pre-update token log probabilities and group-standardized sequence rewards. This is a small GRPO-style implementation, not a claim of reproducing a specific full GRPO training recipe.

RL reward is1 for a correct, complete numeric boxed answer in the generated continuation that terminates within budget; otherwise0. A capped or excessively repetitive rollout receives a0.1 penalty. On alternating updates the input is either the original question or that same question followed by a frozen-proxy process prefix. Both sources are rewarded for correctness. Prefix source is used only by the data sampler, never added to model input. Fresh full-question rollouts are generated by the current teacher, so the preservation signal includes its current on-policy contexts.

## Process objective and its limits

The auxiliary objective is KL(p_frozen_proxy || p_teacher) on selected middle positions of cached proxy rollouts. Query tokens, the first32 response positions, special tokens, and the final answer region are excluded. The first boxed/final-answer marker is located using actual decoded token prefixes with an8-token preceding margin; without a marker, the last32 positions are conservatively excluded. This is an operational mask, not a semantic proof that every selected token is purely reasoning.

Because the model output heads have different padding sizes, the teacher is sliced to the151936-dimensional proxy head before normalization, matching the existing MiniLLM single-step KL. Teacher native generation retains its152064-dimensional head. The existing OPD reward also has its own full-head normalization; auxiliary convergence is therefore not evidence that every term in the entire OPD trainer is zero.

At identical distributions, the KL-distillation loss and its student gradient are zero for this matched proxy/context. That is the local fixed-point motivation. The proxy can move during actual OPD, other losses may remain active, and future students may differ. Reducing this auxiliary loss does not prove stable anti-distillation.

The proxy is used only during training. This pilot is **hybrid RL plus a logit auxiliary objective**, not meta-RL with student-after-training performance as the reward. That expensive inner loop is not implemented here.

## Data and evaluation

Reuse the audited384-prompt GSM8K TRAIN context cache, with320 training and64 validation prompts. All sources of a question remain in the same partition. Ground truths and prompt tokenization are checked against the original training prompt file and its hash. Process probes use fixed validation rows and are diagnostic, not the optimization reward.

Each exported teacher is evaluated in greedy, ordinary sampling, and full sampling modes. Actual OPD starts from the same0.5B14B-CoT-SFT student, uses the unchanged120-step seed10 protocol, and compares with the original-teacher clean run. The joint student is additionally compared directly with the outcome-only student. Historical test0:200 is exploratory; extra test600:800 evaluation reuses the earlier confirmation slice and is not a newly untouched test set. Neither arm is selected using student scores.

The sequential queue first completes training,64-example teacher evaluation and120-step OPD for each arm, then expands teacher/student evaluation as existing allocation time permits. Skipped or interrupted phases are explicitly recorded. Final-answer-only/process-only OPD ablations and new students are not yet implemented in this first pilot.

## Verification and records

CPU objective checks verify zero KL and gradient at identical distributions, finite zero advantages for constant-reward groups, and the signs of the policy gradient. A two-update GPU smoke test checks real forward/backward, memory, and merged model export before the formal queue can launch. The smoke test is not an efficacy result. Failed smoke attempts are retained separately.
