# Separate target efficacy from teacher fitting: sparse oracle diagnostic

The user discussion on September12 identified two possible bottlenecks: the desired output modification itself may be weak, or posttraining may fit it inadequately while damaging ordinary teacher behavior. Two new diagnostic student runs apply targets directly to the immutable original7B teacher during OPD. They are not eligible standalone defenses and make no claim of inference-time source detection or preserved behavior under a realistic detector.

Each starts fresh from the same shortSFT checkpoint49, with the same corrected MiniLLM120-step seed10 protocol. One uses the original Top2 swap and the other the same secondary rank2:17 reversal as the completed tail v1 teacher. The latter retains the documented tied-max argmax caveat. They use only original-teacher logits and fixed vocabulary metadata for probability transformations. The actual student generates its OPD trajectories and is trained as the external diagnostic subject; no teacher parameters are updated, and no student parameter-derived quantity constructs the target.

For each completed response, trim at its first EOS/pad, compute the existing process boundary excluding the final-answer marker and margin, and consider nonspecial positions after offset32. Deterministically sample up to32 positions and select up to8 largest target-KL positions. The seed is a hash of the completed response tokens, so reward and KL paths choose the same positions when scoring the same response. This is explicitly retrospective oracle selection, not a strictly causal deployable teacher scoring function. The same transform is applied before probability normalization and impossibility masking in both reward scoring and conditional teacher KL; student logits and its normal generation path remain unchanged.

The sparse intervention is not a mathematical upper bound on effectiveness. It may be weaker than a dense transformation and can differ from a fitted teacher's broad incidental changes. The trajectories are on-policy for the resulting student, so oracle and fitted runs need not visit identical contexts. A strong oracle/weak fitted result would motivate investigating fit and selectivity; a weak sparse oracle result would question this sparse target recipe, not prove every related target or density impossible. Conversely, successful student suppression with a perfect source trigger would not establish a realizable teacher-only defense.

Both diagnostics have a separate2-update startup test, then a fresh120-update run and main400 evaluation. The startup test requires actual target positions in both reward and regularizer paths. Helper tests verify deterministic reward-KL parity, at most8 modified positions, prefix/final-region and special/padded vocabulary protection, and no-op padding cases. Initial CPU testing exposed a missing get_vocab method in the fake tokenizer; it was repaired before any GPU diagnostic launched. Target transformers are cached by tokenizer to avoid repeated vocabulary construction. No running training script was overwritten.

In parallel, the projected teacher's completed main400 result is extended to another600 student questions and400 teacher questions. A fresh original-teacher anti1.5/anchor12/answer1/RL2 control omits the projection, keeping the remaining recipe identical, to assess whether the projection rather than its changed anti weight accounts for the outcome. These tests preserve the existing teacher-quality screens and external student budget.

`oracle_role_target.py` applies sparse Top2 only in one path: either the observed-token teacher log-score used by the reward computation, or the full conditional teacher distribution used by the regularizer. The other path returns exact original logits. Both retain the same original teacher, fixed student protocol and retrospective known-source selection, and remain diagnostic/ineligible standalone defenses. ## September12 identity scoring-entry control

The dedicated diagnostic entry overrides the teacher conditional-logit method in addition to its reward scoring hook. An exact-logit identity control is therefore warranted to check whether the wrapper itself reproduces ordinary clean OPD under the same initialization and120-update protocol. This is not a new defense or a mechanical efficacy seed repeat. Both scoring roles return the original tensor unchanged, including dtype and masked values, and record zero interventions. Student performance and runtime updates must be compared with the ordinary clean baseline before attributing effects solely to target changes.

The first identity helper passed tensor-identity checks but lacked the `mode` attribute consumed by the shared entry's training report. Code review found this while the first attempt was still in its smoke phase. Its own step9870979.7 was terminated; no reservation or sibling experiment was cancelled. The abort sidecar and original files are retained. Separatev2 helper/entry/shell/driver files add the attribute and an interface assertion, use new output names, and restart from fresh SFT. Existing sparse/coverage/role helpers already provide `mode`; this defect was confined to the newly added identity helper. No active file was overwritten. Actualv2 two-update smoke and final120 reproduction remain required.
